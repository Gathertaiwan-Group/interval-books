# 推薦碼與分潤（0039）

給推廣者（團隊成員／外部推廣者）一個推薦碼與分享連結，客人用碼享選品折扣，推廣者按「歸屬毛利」月結分潤。

## 1. 參考 Realreal 之後的取捨

Realreal 有兩套：KOL 連結（`kol_ref` cookie 7 天、`commission_rate` × 訂單 total）與會員推薦碼（`member_ref` cookie 30 天、雙方各 50 點）。我們沿用的是「cookie 30 天、最後一次點擊為準、結帳可手打」這個歸屬模型。下面幾點刻意做得不一樣：

| Realreal 的問題 | 這裡的做法 |
|---|---|
| cookie 設在前台網域，API 在另一個主機，`fetch` 沒帶 credentials，所以歸屬多半送不到 | 結帳頁把碼放在 payload 裡明確送出，cookie 只當沒送欄位時的後備 |
| KOL 的優惠券會蓋掉客人自己打的碼 | 客人打的碼優先；客人清空欄位就不套任何碼 |
| 分潤按 `orders.total` 算，含運費、未付款、已取消、已退款 | 只算已付款且沒取消、沒退款的單；基礎是選品毛利，不含運費與票券 |
| 沒有結算紀錄 | `referral_settlements`，以 unique(推廣者, 月份) 防止同一個月付兩次，另存逐筆快照供扣回使用 |

## 2. 資料（migration 0039，只新增）

- `referrers`：推廣者。欄位有 name、code（大寫英數 2–20 碼，unique）、kind（`team`／`external`）、contact、email／phone（排除自購用）、base_salary（只記錄）、discount_percent（NULL 表示用預設）、commission_tiers（NULL 表示用全站級距）、active、note。
- `referral_settings`：單列全站預設，後台有一張設定卡可以改。

  | 設定 | 預設值 |
  |---|---|
  | 客人折扣 | 5% |
  | 估算毛利率 | 35% |
  | 分潤級距（累進） | 0–1 萬 15%、1–3 萬 20%、3 萬以上 25% |
  | 新客倍率 | ×1.25 |
  | 團隊獎金池門檻 | NULL，即不計算 |
  | 獎金池比例 | 5% |
  | 獎金池平分比例 | 50% |
  | 發放上限 | 當月選品毛利的 40% |
  | 退款扣回期限 | 30 天 |

- `referral_settlements`：月結紀錄，記錄推廣者、月份、金額（分潤＋獎金池－扣回，可以是負數）、snapshot（逐筆分潤、扣回清單、上限比例）、結算人與時間。
- `orders` 新增三欄：`referrer_id`、`referral_code`、`referral_discount_percent`。折扣金額寫進既有的 `orders.discount`，所以金流（黑貓／PayUni／匯款）與發票（負數折扣列）都不用改。
- 授權與 0005 相同：RLS 開啟、零 policy、revoke anon／authenticated、只 grant service_role。前台查碼走 server fn，只回折扣 %。

## 3. 前台

- 任何頁面帶 `?ref=CODE`，`ReferralCapture` 會在瀏覽器寫入 `ib_ref` cookie（30 天、SameSite=Lax）。刻意不在伺服器端 Set-Cookie，因為公開頁面會被 CDN 快取。
- 結帳頁有「推薦碼」欄位，預設帶入 cookie 裡的碼，並即時顯示折扣或「無效」。
  - 自己打的碼無效時，訂單不會成立（`referral_invalid`），避免照原價收錢。
  - cookie 帶進來的碼無效時，靜默忽略。
- 折扣 = round(選品／書籍小計 × %)，介於 0 和小計之間。票券（event／journey）與運費不打折。免運門檻仍看折扣前的小計。
- 完成頁與後台訂單詳情會顯示推薦碼。

## 4. 月結規則（`src/lib/referral.ts` computeMonthlyReport）

1. **哪些訂單算數**：`paid_at` 落在該月（台北時間）、`payment_status = paid`、沒取消、不是沙盒單。
2. **毛利**，每一行選品分開算：
   - 折後營收減成本。
   - 進銷存 `cost_price × units_per_sale` 只有在 0 < 成本 < 售價時才採用。其他情況一律用「折後營收 × (1 − 估算毛利率)」估算，報表會標「估」。
   - 單筆毛利不會是負數。
3. **歸屬毛利 G**：該推廣者名下各單毛利的總和，自購的單（email 或手機與推廣者登記的相同）不算。自購的單仍然給客人折扣，只是不計分潤。
4. **分潤**：先用累進級距算 G 的基本分潤，得出平均費率 r。每一單的分潤 = 毛利 × r，新客再乘以新客倍率。新客的定義：同一個 email 或手機，在這張單之前沒有任何付過款的單。
5. **團隊獎金池** = (當月線上選品營收 − 門檻) × 5%，由啟用中的團隊成員分：
   - 50% 平分。
   - 50% 按各人的歸屬毛利占比分；如果大家的歸屬毛利都是 0，這一半也平分。
   - 外部推廣者不參與。
6. **發放上限**：全部分潤＋獎金池超過「當月選品毛利 × 40%」時，所有人的分潤與獎金池等比例縮減，報表會顯示縮減比例。
7. **扣回**：已結算月份裡的訂單，如果在該月結束後 30 天內被取消或退款（依 `cancelled_at`，沒有就用 `updated_at`），就從下一個尚未結算的月份扣掉當時付出的金額。每筆只扣一次，報表顯示為負數。
8. **應付** = 分潤 + 獎金池 − 扣回。「標記已結算」由伺服器重算後寫入，只能結已經過完的月份。

## 5. 後台

`/admin/referrals`（推廣與分潤）包含：

- 月份選單
- 摘要卡（選品營收、毛利與其中估算的行數、分潤、獎金池、應付）
- 上限警告
- 每位推廣者的卡片（訂單明細、新客／舊客、自購、扣回、標記已結算）
- CSV 匯出
- 推廣者管理（新增、編輯、停用、複製連結）
- 全站預設設定卡

每一支 server fn 都掛 `adminFnMiddleware`。
